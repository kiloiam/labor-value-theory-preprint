说明

若发现文本、元数据或引用信息有误，优先在规范仓库的公开 Issue 中说明具体位置与依据。本站不公开私人邮箱，也不通过即时通讯账号接收勘误；这样做是为了保持去标识化边界一致。

更正方式是发布新版本而非静默替换已发布文件：Zenodo / Figshare 的版本 DOI 与 GitHub Release 资产保持不可变，新版本在元数据与版本史中说明变更，旧版本仍可核对。站内页面与校验表随新版本同步重算。

撤稿需给出理由，并且通常不会让已分发的副本消失：预印本服务器与 Web 存档的历史快照一般保留。因此本站把「已发布即长期可见」作为前提，任何投递前都应核对作者署名、许可与版本。

隐私处理：早期含其他姓名标识的 Figshare 历史记录已由作者提交下架工单，等待官方执行。相关完整链接仅存在于工单材料中，该页面已设置 `noindex` 并从站点地图移除；请勿在传播物料中复述该记录。

常见问题

发现错字怎么反馈？
在规范仓库开公开 Issue，注明位置与依据。
能直接改掉已发布的 PDF 吗？
不能。发布新版本并保留旧版本，才能保持可复核性。
下架工单现在什么状态？
已提交，等待平台官方执行；期间不传播该历史链接。
